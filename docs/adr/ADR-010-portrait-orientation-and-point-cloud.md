# ADR-010: 縦持ち基準の座標系整備と色付き点群

**ステータス**: 完了  
**日付**: 2026-09-05  
**リリース対象**: v1.2

---

## コンテキスト

縦持ち（ポートレート）でスキャンすると、以下の不具合があった。

1. 保存した RGB フレームのプレビューが左に 90° 回転して表示される
2. メッシュプレビューの既定ビューも左に 90° 回転している
3. メッシュが真っ白で、形状の判別がしづらい

原因は ARKit の座標系・画像の向きの定義にある。

- `ARFrame.capturedImage` はセンサ基準（横長）で格納される。
  `UIImage(cgImage:)` は既定で `.up` 扱いとなるため、縦持ちで撮影した画像がそのまま横倒しで保存されていた。
- `ARCamera.transform` の座標系はランドスケープ（ホームボタン右）基準で定義されており、
  縦持ち時は **+X が画面下方向**、**+Y が画面右方向**、**+Z が画面手前** になる。
  v1.1 までは相対座標系を `inverse(initialTransform) * transform` としていたため、
  この「横倒しのカメラ座標系」がそのまま `poses.json` と `mesh.obj` の基準になっていた。
- ARKit のシーン再構成メッシュは色情報を持たないため、既定マテリアルでは白く描画される。

## 決定事項

### 1. 相対座標系は「スキャン開始時のポートレート表示」基準

`CoordinateSystem.portraitAlignment`（Z 軸まわり -90°、`(x, y, z) -> (y, -x, z)`）を
初期姿勢の逆行列に前置し、相対座標系を次のとおり定義する。

| 軸 | 向き |
|---|---|
| +X | 画面右方向 |
| +Y | 画面上方向（縦持ちでは概ね鉛直上向き） |
| +Z | 画面手前（カメラ後方） |

- 姿勢: `relativeTransform = portraitAlignment * inverse(initial) * current`
- メッシュ: `referenceTransform = initial * inverse(portraitAlignment)` を
  `MeshExporter.chunk(from:referenceTransform:)` に渡し、姿勢と同一基準へ揃える
- 副次的に「軌跡 (XZ 平面)」が水平面の軌跡となり、意味のある表示になる

代替案として「プレビュー側だけ回転させる」も検討したが、`poses.json` と `mesh.obj` の
座標系定義そのものが横倒しである問題は解決しないため不採用とした。

### 2. 画像の向きは EXIF で表現する（ピクセル配列は変更しない）

`colorToJPEGData` / `depthPreviewImage` で `UIImage.Orientation.right`（時計回り 90°）を付与する。

- ピクセル配列はセンサ基準のままなので、`poses.json` の内部パラメータ
  (`fx`, `fy`, `cx`, `cy`) との整合が保たれる
- EXIF を解釈するビューア（iOS・macOS プレビュー・Pillow など）では正立表示される
- 後処理でピクセルを直接扱う場合は、EXIF を無視すれば従来どおりセンサ基準で読める

### 3. 色情報は「色付き点群」で提供する

メッシュへのテクスチャ貼り付け（多視点テクスチャベイク）は、UV 展開・可視性判定・
露出合わせが必要で v1.2 のスコープでは実現できない。代替として、保存済みの
RGB フレームと深度マップから色付き点群を生成する。

- `PointCloudExporter`: 深度画素を内部パラメータで逆投影し、同一 FOV のカラー画像から色をサンプル
- 出力先: `sessions/<UUID>/points.ply`（PLY binary little endian、XYZ + RGB）
- 上限: 最大 40 フレーム / 約 20 万点。超える場合は画素を間引く
- 深度の採用範囲: 0.1〜5.0 m（`NaN` / 0 は除外）
- 詳細画面でメッシュ / 色付き点群を切り替えてプレビューでき、PLY 単体の共有も可能

### 4. 3D プレビューの既定カメラを明示する

`MeshPreviewView` はジオメトリのバウンディングボックスから距離を算出し、
`+Z` 側から `-Z` 方向を見るカメラノードを追加する。相対座標系では +Y が上のため、
スキャン時と同じ正立した既定ビューになる。

## 検証基準

- [x] 縦持ちで撮影した RGB フレームが詳細画面で正立表示される
- [x] 深度プレビューも RGB と同じ向きで表示される
- [x] メッシュプレビューの既定ビューが正立する（実機確認）
- [x] `points.ply` が生成され、色付き点群としてプレビュー・共有できる（実機確認）
- [x] `swift test` (Linux) が成功する

## 影響

- **破壊的変更**: v1.1 以前に保存したセッションの `poses.json` / `mesh.obj` は
  横倒しのカメラ座標系のままであり、v1.2 以降のものと座標系が異なる
- スキャン開始フレームの `quaternion` は単位クォータニオンではなく、
  Z 軸まわり -90° の回転になる（`translation` は従来どおり原点）
- 点群生成は保存時に JPEG のデコードを伴うため、保存時間がフレーム数に応じて増える
